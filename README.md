## Executive Summary

**Commitment Issues** is a lightweight automation framework designed to streamline Git commit generation through a configurable, reproducible, and developer-oriented workflow.

By combining randomized commit messaging, controlled execution limits, and repository-level change tracking, this project explores the intersection of developer productivity and the psychological need to see green squares.

### Core Objectives

- Standardize repetitive commit generation workflows.
- Improve operational efficiency through automation.
- Maintain a transparent and auditable commit history.
- Demonstrate practical Git and Python subprocess integration.
- Investigate why developers care so much about tiny green rectangles.

## Installation & Deployment

### Prerequisites

- Python 3
- Git
- A Git repository
- A functioning keyboard
- An acceptable relationship with your own decisions

### Quick Start

Clone the repository:

```bash
git clone <YOUR-REPOSITORY-URL>
cd commitment-issues
```

Execute a standard commit operation:

```bash
python spam.py daily
```

Execute a controlled burst:

```bash
python spam.py burst 5
```

Push changes to the remote repository when ready:

```bash
git push
```

**Note:** Burst execution is bounded by the configured `MAX_BURST` value. Review the configured limit before running the command.

## Security & Responsible Usage

This project modifies Git history by creating real commits in the local repository.

- Review generated changes before pushing.
- Keep commit history meaningful in repositories used for actual collaboration.
- Do not use this tool to misrepresent work, contributions, or professional experience.
- Keep your expectations realistic.

The software is provided as-is, without warranties, guarantees, or emotional support.
